## 解題說明

本作業的目標是設計一個 C++ `Poly`類別。根據作業要求，我們必須使用帶有 **Header Node ** 的 **Circular Linked List ** 來儲存多項式的每一項。每一項資料包含係數 (`c`) 和指數 (`e`)。

為了提升記憶體效率，作業要求實作 **Available List** 機制。當節點被刪除時，不直接歸還給系統，而是存入一個靜態的 `Avail` 串列；當需要新節點時，優先從 `Avail` 取出，減少 `new` 和 `delete` 的次數。

## 程式實作

程式碼包含以下核心元件：

1.  **Node (節點類別)**：儲存 `Term` (係數與指數) 與下一個節點指標 `n`。
2.  **Avail (記憶體管理)**：這是一個靜態類別，負責管理閒置節點。
    * `get()`：從閒置串列取用節點，若無則 `new`。
    * `ret()`：將單一節點歸還至閒置串列。
    * `retChain()`：將整串鏈結串列歸還。
3.  **Chain (鏈結串列)**：實作帶 Header 的環狀串列。
    * 建構子建立指向自己的 Header。
    * `ins()` 負責按指數降冪插入節點，若指數相同則合併係數。
4.  **Poly (多項式類別)**：
    * 實作 `operator>>` 與 `operator<<` 進行輸入輸出。
    * 實作 `operator+`, `-`, `*` 進行多項式運算。
    * 實作 `Evaluate` 計算多項式在特定 $x$ 的值。
    * 實作 Copy Constructor 與 Assignment Operator `=` 以正確處理深層複製。

## 效能分析

假設多項式 A 有 $N$ 項，多項式 B 有 $M$ 項：

1.  **時間複雜度**：
    * **加法 (+)** 與 **減法 (-)**：程式會遍歷兩個多項式，類似合併排序的過程，複雜度為 $O(N + M)$。
    * **乘法 (*)**：需將 A 的每一項與 B 的每一項相乘，再插入結果。最差情況下為 $O(N \times M \times (N+M))$ (因插入時需搜尋位置)。
    * **Evaluate**：遍歷多項式一次，複雜度為 $O(N)$。

2.  **空間複雜度**：
    * 每個多項式佔用 $O(N)$ 的節點空間。
    * `Avail` 串列的大小取決於程式執行過程中曾同時存在的最大節點數，能有效重複利用空間。

## 申論及開發報告

### 1. 為何使用環狀鏈結串列與 Header Node？
在作業中使用 Header Node (頭節點) 能大幅簡化程式邏輯。因為串列永遠非空 (至少有一個 Header)，所以在插入或刪除節點時，不需要特別判斷「是否為第一個節點」或「串列是否為空」的邊界情況。配合環狀結構 (最後一個節點指回 Header)，只要判斷指標是否等於 Header (`p != h`) 即可知道是否遍歷結束，這讓程式碼更簡潔且不易出錯。

### 2. Available List 的效益
[cite_start]傳統的 `new` 和 `delete` 是系統呼叫，開銷較大且容易造成記憶體破碎。本作業實作的 `Avail` 類別充當了一個物件池 (Object Pool)。當多項式被 `Delete` (解構) 時，節點並不會真正消失，而是串接到 `Avail` 串列中 [cite: 54]；當需要建立新項次時，直接從 `Avail` 拿取即可。這在頻繁進行多項式加減乘運算時，能顯著提升效能。

### 3. 開發心得
本次作業整合了鏈結串列操作與運算子多載。最困難的部分在於實作 Assignment Operator (`=`) 與 Destructor (`~Poly`) 時，必須確保記憶體正確回收至 `Avail` 串列，否則會造成 Memory Leak。透過將變數命名簡化 (如 `p`, `t`)，雖然程式碼變短，但仍需謹慎處理指標的連接與斷開，才能確保環狀結構的正確性。
